# 鼠洞 · 总体设计

> 状态：草案，待评审。表结构见[数据表](data-model.md)，接口细节见[接口](api.md)。

## 1. 目标

- **群的超集**：论坛以 QQ 群为基础，群里的问答、经验和通知由 bot 同步过来，论坛上也可以独立发帖。论坛的内容不同步回群里，群里只会收到开奖结果和二期的播报，都只有标题和链接；通知用邮件发给本人（第 8.6 节）。
- **沉淀内容**：存到论坛的内容长期保留，群被封也不会丢。
- **和 QQ 群打通**：一个 QQ 号就是一个账号，资料默认和群里一致。AstrBot 插件可以通过接口使用论坛的几乎全部功能，并指定以哪位群友的身份操作。
- **轻量**：和其他服务共用一台服务器，论坛进程空载约 100MB、高峰不超过 200MB，支撑上千人的群和两位数并发。服务器出口带宽只有 25Mbps，页面和图片都要尽量小。

暂不做：站内私信（QQ 里就能私聊）、联邦协议。

## 2. 已定决策

| 事项 | 决定 |
| --- | --- |
| 名称 | 鼠洞 |
| 仓库与域名 | `mousebaoyan/mousehole`，`bbs.mousebaoyan.cn` |
| 实现方式 | 自研，借鉴 Discourse、Apache Answer、V2EX、贴吧和 NGA 的设计 |
| 技术栈 | React 19 + React Router 8 + Hono 全栈，TypeScript 7，页面和接口在同一个 Node 进程；依据见第 5 节 |
| 数据库 | 复用服务器上 1Panel 的 PostgreSQL 18，新建独立的库和账号；暂不用 Redis |
| 和群的关系 | 论坛是群的超集：群里的内容同步过来，论坛上也能独立发帖；论坛的内容不同步回群里 |
| 身份 | 一个 QQ 号就是一个账号，第一次登录就是注册，之后永久保留，暂不提供注销；名字、头像、个性签名默认取 QQ 的，可以自己改；群角色和专属头衔从 QQ 同步 |
| 等级 | 论坛自己的等级 L0–L5，和群等级无关：按论坛里的活跃情况自动升降，从群里同步来的内容也算，L5 由管理员授予；不同等级权限不同，版块可以设等级门槛 |
| 成员资格 | 在群里才是成员。退群或被踢后账号冻结，权限等同访客，发过的内容保留；重新进群自动恢复 |
| 群信息同步 | 由 bot 推送，同时支持增量和全量；不重要的信息可以隔久一点同步 |
| 登录 | 三种都支持：口令登录、一次性链接登录（这两种经 bot 验证）、QQ 邮箱验证码 |
| 公开范围 | 公开可读；版块可以设为仅成员或某个等级以上可见；每个人可以设置自己的内容不给访客看。访客看不到的内容，搜索引擎也收录不到 |
| 术语 | 帖子、楼层、主楼、回复、楼主，全站统一，见[开发约定 · 术语](development.md#6-术语) |
| QQ 号 | 不做隐私处理，成员之间可见，和群里一样；访客默认看不到。想隐藏身份的发匿名帖（第 8.12 节） |
| bot 代发 | 标注来源；本人可以编辑、删除，也可以关闭代发；审计日志记录操作人 |
| 内容审核 | 论坛提供审核状态、接口和事件，具体审核以后接入 LLM |
| 系统配置 | 在管理后台里配置，包括 SMTP；环境变量只留数据库连接、站点地址和加密密钥；站点名称、简介和 Logo 写成常量 |
| bot 插件 | AstrBot 插件也由我们开发，放在 `mousebaoyan` 组织下的独立仓库（第 14 节 M9） |
| 许可证 | MIT |

## 3. 为什么自研

现成论坛都要深度改造，才能满足三件核心需求：QQ 号即身份、bot 代任意群友操作、通过 bot 登录。

| 项目 | 技术栈与资源 | 代任意用户操作 | 主要问题 |
| --- | --- | --- | --- |
| Discourse | Ruby + PostgreSQL + Redis，官方建议 2GB 以上内存 | 支持（`Api-Username`） | 太重 |
| Flarum | PHP + MySQL | 支持（API key + userId） | QQ 登录、成员同步要写 PHP 扩展 |
| NodeBB | Node + Redis 或 MongoDB | 支持（master token + `_uid`） | QQ 登录、成员同步要写插件 |
| Apache Answer | Go，问答型 | 不支持 | 只适合纯问答 |

QQ 互联也用不上：它要求域名完成 ICP 备案（服务器在香港，无法备案），而且只返回 openid，拿不到 QQ 号，没法和群里的身份对应起来。

## 4. 架构

```text
QQ 群（可以有多个）
  ⇅ NapCat
AstrBot + 论坛插件
  │  REST：Bearer token + X-Act-As: qq:号码
  │  SSE 事件流：插件主动连接，断线后按游标续传
  ▼
OpenResty（1Panel，TLS） ◀── 浏览器
  ▼
mousehole 容器（Hono + React Router 8，Node 26）── 图片目录（数据卷）
  ├─ 页面：服务端渲染，浏览器端接管交互
  ├─ /api/v1：网页和 bot 共用的 JSON 接口
  ├─ SSE：网页实时更新、bot 事件流
  └─ 定时任务：批量写浏览数、计算等级、清理过期数据、刷新头像
  ▼  1panel-network
1Panel 的 PostgreSQL 18（mousehole 库）
```

- **一个进程**：Hono 是整个应用的 HTTP 服务器，`/api/v1` 由 Hono 处理，其余路径交给 React Router 渲染页面。服务端渲染页面时在进程内调用接口，不经过网络。
- **接口是唯一入口**：业务逻辑都在各业务模块的服务里（`server/modules/*/service.ts`），网页和 bot 都通过 `/api/v1` 调用。网页能做的，bot 都能做。
- **插件主动连接**：插件所在的机器可以在内网，只要能访问外网即可。插件主动调用接口、主动订阅事件流，论坛不会反向连接插件。
- **论坛不依赖 bot**：bot 离线时论坛照常使用，新用户也能用邮箱验证码登录，只是群信息暂停同步。期间产生的事件留在论坛里，bot 恢复后补发。

## 5. 技术选型

### 5.1 选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 运行时 | Node.js 26 LTS，pnpm | 2026 年 10 月 28 日转为 LTS，支持到 2029 年 4 月 |
| 语言 | TypeScript 7 | Go 实现的编译器，类型检查快 8–12 倍 |
| 前端 | React 19，开启 React Compiler | 编译时自动做组件级的性能优化，不用手写 memo |
| 全栈框架 | React Router 8（框架模式） | 服务端渲染，SEO 和 QQ 链接卡片都正常；路由参数和 loader 数据都有生成的类型 |
| HTTP 与接口 | Hono + `@hono/zod-openapi`（Zod 4）；用 `react-router-hono-server` 把 React Router 接进 Hono | Hono 是整个应用的 HTTP 服务器；接口定义同时用于校验请求和生成 OpenAPI 3.1 文档 |
| 数据库 | PostgreSQL 18（复用 1Panel 实例）+ Kysely + `pg` | 迁移直接写 SQL，类型由 kysely-codegen 从数据库生成 |
| 搜索 | PostgreSQL 全文检索（tsvector + GIN），中文在应用里二元切分 | 实例里没有中文分词扩展，这样做不用装任何扩展 |
| 缓存 | 进程内缓存 | 单进程足够，暂不用 Redis。以后要跑多个进程时，缓存和限流换成 Redis，实时推送用 PostgreSQL 的 LISTEN/NOTIFY |
| 样式与组件 | Tailwind CSS v4 + shadcn/ui（底层 Base UI） | 配色取自鼠群 logo，深色模式的切换方式沿用主站；组件代码复制进仓库，由我们自己维护。界面上的控件（下拉框、复选框、对话框、确认框等）都用这套组件，样式统一，不用浏览器原生的样式和弹窗；每个页面都加载的部分尽量不引入 Base UI，见[开发约定 §4](development.md#4-前端) |
| 正文 | Markdown（markdown-it），服务端渲染，再用 xss 按白名单过滤；highlight.js 代码高亮 | 网页和 bot 发的内容走同一套渲染。高亮用 GitHub 的浅色、深色配色，和主站一致；不用 Shiki，它的 C++ 语法一种就要占 100MB 以上内存 |
| 图片 | sharp | 转 WebP、去 EXIF、限尺寸 |
| 邮件 | nodemailer + SMTP | SMTP 在管理后台配置，可以配几个邮箱轮流顶上；用 QQ 邮箱发信，发往 qq.com 不容易进垃圾箱 |
| 实时 | SSE（Hono 的 `streamSSE`） | 只需要服务端单向推送，经过反向代理也简单 |
| 代码检查 | oxlint + tsgolint（含需要类型信息的规则）、Prettier | 基于 TypeScript 7，比 ESLint 快一个数量级 |
| 测试 | Vitest（单元、接口）、Playwright（关键页面）、`scripts/load-test.ts`（压测） | 接口测试连真实的 PostgreSQL；压测脚本用 Node 自带的 fetch，和 mock-bot 共用演示群，不另装工具 |
| 部署 | GitHub Actions 构建镜像推到 GHCR，服务器用 docker compose 拉取运行 | 服务器不编译 |

### 5.2 选型依据

代码全部由 AI 编写，所以首要标准是：AI 写出来的代码对不对，写错了能不能马上被发现。其次才是性能和内存。

**React，不用 Vue**

- **AI 写 React 更准**：[Web-Bench](https://arxiv.org/html/2505.07473v1) 用同样的题目测试各框架。同一个 Claude 模型写 React 得 60–65 分，写 Vue 得 30–40 分；全栈框架 Next 得 35–40 分，Nuxt 得 25 分。论文给的原因是 React 的训练数据最多，JSX 的信息密度高。
- **类型检查**：TSX 就是 TypeScript，可以直接用 TypeScript 7 和基于它的 oxlint。Vue 的 vue-tsc 要等 TypeScript 7.1 提供编程接口（还没有日期，见 [vuejs/language-tools#5381](https://github.com/vuejs/language-tools/issues/5381)），在那之前只能用 TypeScript 6。类型错误是 AI 发现问题最主要的手段，检查越快、越完整越好。
- **生态**：shadcn/ui 是 AI 生成界面最常用的组件体系；论坛要用的编辑器、表情选择、图片查看等组件，React 的选择也最多。
- **性能不构成区别**：Vue 的服务端渲染更快，但在同样的内存限制下差距不大，两者的吞吐都远高于需要，见下表。

**React Router 8，不用 Next.js、TanStack Start 或 Nuxt**

本机实测条件：渲染同一个有 30 条帖子的列表页，每次请求都服务端渲染，V8 堆上限 128MB，Apple M4，Node 26。

| 框架 | 空载内存 | 压测后内存 | 每秒请求数 | HTML 大小 |
| --- | --- | --- | --- | --- |
| React Router 8 + Hono | 71MB | 118–162MB | 560–590 | 32KB |
| Nuxt 4.6 | 61–65MB | 129–163MB | 630–860 | 30KB |
| Next.js 16.4 | 80–100MB | 132–171MB | 130–180 | 60KB |

- **Next.js**：吞吐只有四分之一，HTML 大一倍（页面内容在 RSC 数据里重复了一遍），自己部署时有人报告过内存泄漏。服务端组件和客户端组件的边界，也是 AI 最容易写错的地方。
- **TanStack Start**：类型安全最好，但还是 1.0 候选版，几天发一个版本。
- **Nuxt**：Nuxt 5 会换用 Nitro v3 和 h3 v2，目前还在测试，现在写的服务端代码以后要迁移一次；Nitro 的 OpenAPI 生成也还是实验功能。
- **React Router 8**：2026 年 6 月发布，改动刻意做得很小。之后每年一个大版本，和 Node LTS 对齐；采用开放治理，由 Shopify 团队维护。

**Hono + `@hono/zod-openapi`**：bot 接口是最重要的功能。每个接口用 Zod 写一份定义，覆盖参数、请求头和每种状态码的响应。同一份定义既校验请求，又生成 OpenAPI 文档，所以两者不会对不上。页面的服务端代码在进程内调用这些接口，保证网页能做的 bot 都能做。

**Kysely，不用 Drizzle 或 Prisma**：表结构用到了部分索引、`INCLUDE`、`fillfactor`、lz4 压缩、xid8 和 tsvector，Drizzle 和 Prisma 的建表语法都表达不全；Drizzle 1.0 也还是候选版。Kysely 只负责类型安全地写查询，迁移就是[数据表](data-model.md)里写好并验证过的 SQL。查询和 SQL 一一对应，方便用 `EXPLAIN` 调优。

**一种语言、一个进程**：不另外起 Go 或 Rust 服务。服务端渲染本来就离不开 Node，拆成两个服务也省不了内存。同一份 Zod 定义前后端共用，类型从数据库一路打通到页面。

### 5.3 以后容易换的

Markdown 渲染、中文搜索、图片处理、发邮件、定时任务和编辑器都在服务层后面，替换时不影响接口和数据，现在不必纠结。

## 6. 身份、成员与权限

### 6.1 账号与资料

- 一个 QQ 号对应一个账号，QQ 号不能改。bot 同步群成员时为每位成员建号，这时账号是"未激活"状态；本人第一次登录就是注册，账号随即激活。bot 代发的内容一开始就记在本人名下。
- 账号永久保留，暂不提供注销。退群后账号冻结（第 6.2 节），内容和资料都还在。
- 名字、头像、个性签名本人可以随时改；没改过的跟着 QQ，改回"跟随 QQ"后重新用 QQ 的：

  | 资料 | 没改过时用 | 限制 |
  | --- | --- | --- |
  | 名字 | 主群的群名片，没有就用 QQ 昵称 | 不超过 24 字 |
  | 头像 | QQ 头像，每天刷新 | 上传的图片和正文图片一样处理 |
  | 个性签名 | QQ 的个性签名，由插件在本人激活时查询后推送（`member.activated` 事件） | 不超过 60 字，QQ 的超出部分截掉 |

- 头像统一转成 96px 的 WebP，由论坛提供（`/avatars/{用户ID}.webp`），访客看到的页面里也就不会出现带 QQ 号的头像链接。
- 名字旁边显示论坛等级（第 6.6 节）和专属头衔，头衔从主群同步。
- 资料卡：QQ 号、群名片、等级、专属头衔、入群时间（显示为群龄）、最近一次在群里发言的时间和个性签名。
- QQ 号对登录的成员可见。访客和搜索引擎看不到，就像群外的人看不到群成员一样，也防止被批量抓取；站点设置可以改成对所有人公开。
- 群里的其他机器人同步为 `bot` 角色，不能登录，也不进排行榜。

### 6.2 成员资格

- 在任意一个启用的群里就是成员；都不在了，账号就冻结。主动退群和被踢一样处理。
- 冻结期间，权限和访客一样：不能发帖、回复、点赞、收藏，看不到有门槛的版块和 QQ 号，也不再收到通知，bot 也不能代为发内容。仍然可以登录，但只能查看和导出自己的内容。
- 发过的内容照常显示，资料卡上标注"已不在群里"。很多回答对后来的人有用，不应该跟着人一起消失。
- 重新进群后自动恢复，内容、设置、等级都还在，不用重新注册。
- 群被封后，在后台停用旧群、关联新群。只在旧群里的人会先被冻结，加入新群后恢复。

### 6.3 群信息同步

bot 把 QQ 群的信息推送给论坛。两种方式都支持，推荐一起用：

- **增量**：bot 收到进群、退群、改群名片等 QQ 通知时，立即推送这一个人的变化。实时、省流量，但 bot 离线期间会漏。
- **全量**：bot 定期推送完整成员名单，论坛自己比对出谁进群、谁退群、谁改了资料，把漏掉的补上。准确，但费流量。

两种方式用同一种成员记录，字段名和 NapCat 返回的一致，可以原样转发。每条记录只带要更新的字段，没带的字段保持不变，所以不重要的字段可以隔久一点再带。另外有三个保护：

- **乱序**：每次推送都带上读取时间，旧数据不会覆盖新数据，到达顺序乱了也没关系；早于最近一次全量的推送也不再生效。
- **写入量**：论坛只写有变化的行，最后发言时间按小时取整后再比较。每分钟推一次全量，也不会让数据库越写越大。
- **名单不全**：一次全量比上次少了超过 20% 的人，先不处理，等下一次全量确认。这样 NapCat 偶尔返回不完整的名单时，不会把一大批人误冻结。

推荐频率：

| 内容 | 方式 | 频率 |
| --- | --- | --- |
| 进群、退群、被踢、管理员变动、群名片、专属头衔 | 增量 | 收到通知时 |
| 完整成员名单，带全部字段 | 全量 | 每小时 |
| 群名、人数、人数上限 | 群资料 | 每小时 |
| 头像 | 论坛自己从 QQ 头像接口拉 | 每天 |

全量读的是 NapCat 自己维护的成员缓存，不让它为此去 QQ 服务器拉名单：频繁拉成员列表容易被 QQ 风控。NapCat 在启动时、有人进群退群时都会自己刷新这份缓存，所以每小时读一次就够新（[插件设计](https://github.com/mousebaoyan/astrbot_plugin_mousehole/blob/main/docs/design.md)第 6 节）。论坛这边每分钟推一次全量也扛得住。

二期还可以多同步这些：群公告自动同步到论坛公告版；精华消息存档成"群精华"；龙王、快乐源泉这类群荣誉变成论坛徽章；群文件只同步目录，方便在论坛里搜到；群里被禁言时论坛也禁言（后台开关，默认关闭）。

接口细节见[接口 · 成员同步](api.md#4-成员同步)。

### 6.4 角色与权限

角色跟随群角色：群主对应管理员，群管理员对应版主，其余为普通用户，取所在的启用群里最高的那个。管理员可以手动指定角色并锁定，之后同步不再覆盖。论坛的 bot 账号固定为 `bot` 角色。

下表的"成员"指已登录、没被冻结的账号。

| 操作 | 谁可以 |
| --- | --- |
| 浏览公开版块 | 所有人，包括冻结的账号；作者设了不给访客看的内容除外（第 8.10 节） |
| 浏览设了门槛的版块 | 达到门槛的成员 |
| 查看 QQ 号 | 成员 |
| 发帖 | 没被禁言、达到版块发帖门槛的成员 |
| 回复、点赞、短评、收藏、举报 | 没被禁言、能看到这个版块的成员 |
| 编辑自己的内容；删除自己的回复、没人回复过的帖子 | 作者本人，且是成员 |
| 查看、导出自己的内容 | 本人，冻结了也可以 |
| 采纳答案 | 楼主、版主 |
| 置顶、精华、锁定、移动、隐藏、删除任意内容；管理标签 | 版主 |
| 审核内容、处理举报、禁言 | 版主 |
| 封禁、设置角色和等级、管理版块、站点设置、bot token、关联 QQ 群 | 管理员 |

等级高了还有一些管理上的权限，见第 6.6 节。禁言后仍能登录和浏览，但不能发帖、回复、点赞和短评；封禁后不能登录。

### 6.5 bot 代操作

细节见[接口 · bot 认证与代操作](api.md#2-bot-认证与代操作)，要点：

- 每个 bot 一个 token，按范围授权：只读、代发、版主操作、管理、成员同步、登录、事件。
- `X-Act-As: qq:号码` 指定以谁的身份操作，同时受 token 范围和这个人自己的权限限制，不会越权；冻结的账号只能读，不能被代表写入。
- `X-Operator` 记录是谁让 bot 操作的。代表别人操作时，论坛会检查操作人是不是版主或管理员，插件出了 bug 也不会被普通群友利用。
- 成员可以关闭"允许代发"，之后只有他本人能让 bot 以他的身份操作。
- 代发的内容标"来自群聊"或"由机器人代发"，本人可以编辑和删除；所有代操作写入审计日志。

### 6.6 等级

论坛有自己的等级 L0–L5，和群等级无关，参考 linux.do（Discourse 的信任等级）。新账号从 L0 开始，按在论坛里的活跃情况自动升级；从群里同步来的帖子和回复也记在本人名下，一样算活跃。版主和管理员不受等级限制，等级带来的管理权限也管不到他们的内容。

| 等级 | 名称 | 怎么达到 | 新增的权限 |
| --- | --- | --- | --- |
| L0 | 鼠鼠 | 注册 | 浏览、发帖、回复、点赞、短评、收藏、关注、举报。每层最多 2 个站外链接，每天最多发 3 个帖子、20 条回复；从群里同步来的内容不受这两条限制 |
| L1 | 小鼠 | 进入 5 个帖子，读 30 层 | 解除 L0 的限制；私信（二期） |
| L2 | 学鼠 | 在 3 个不同的帖子里回复，获赞 1 次 | 发投票帖和抽奖帖 |
| L3 | 硕鼠 | 访问 10 天；在 10 个不同的帖子里回复；读 100 层，阅读 1 小时；获赞 10 次 | 修改等级比自己低的人发的帖子的标题、版块和标签，只能移到自己能发帖的版块 |
| L4 | 博鼠 | 最近 30 天里：访问 15 天；在 15 个不同的帖子里回复；读 200 层，阅读 2 小时；获赞 20 次；没被禁言或封禁过 | 举报等级比自己低的人的楼层时，这一层先隐藏，等版主处理 |
| L5 | 鼠导 | 管理员授予 | 编辑等级比自己低的人的楼层，锁定和解锁帖子 |

- **管理权限**：L3 起的权限只作用于等级比自己低、又不是版主和管理员的人的内容，也不作用于匿名的内容，否则从能不能操作就看得出匿名的人是几级。L3 改标题记在编辑记录里，改版块和标签记在操作日志里。L4 举报后先隐藏的只是回复，主楼随帖子不在此列；版主驳回这条举报时，这一层恢复。
- **名称**：按读书的路子起：学鼠、硕鼠、博鼠谐音学士、硕士、博士，再往上是鼠导（导师）。等级一律连编号带名称显示，例如"L3 硕鼠"，一眼看出是几级。
- **统计口径**：登录后打开过论坛，或者发了帖子、回复（包括从群里同步来的），这一天就算访问过。进入帖子、读层数和阅读时间来自网页上的阅读记录（第 8.9 节）。"在几个不同的帖子里回复"只算别人的帖子里公开的回复，同一个帖子算一次。获赞把每种表情回应都算上。L1–L3 按累计算，L4 只看最近 30 天，这 30 天里有一天处在禁言或封禁中就不够。数值写成常量，上线后按实际情况调整。
- **升降**：每小时检查今天和昨天活跃过的人，条件够了就升，可以一次升几级。L0–L3 只升不降。L4 每天按最近 30 天复查，达不到就降回 L3，刚升上去的两周内不降。L5 由管理员授予和收回。管理员也可以直接设定某人的等级并锁定，之后自动升降不再改它。冻结和禁言不直接改变等级；冻结期间也不自动升降，回来时等级还在。
- **激励**：
  - 升级时收到通知，默认还会收到邮件；降级不通知。
  - 名字旁边的等级徽标，等级越高颜色越醒目。
  - 本人在个人主页上能看到下一级每项条件的进度，L4 还能看到保级的情况，类似 linux.do 的升级进度页。
  - 设了等级门槛的版块，在侧栏里对还没达到的成员显示锁和需要的等级，点开就是升级进度。
- **按天记录**：累计的统计大多已经有了（第 8.9 节的阅读统计，回复和获赞数）。最近 30 天的要按天记：每人每天一行，记读的层数和阅读秒数，在阅读上报、会话续期和从群里同步内容时顺带写入。

## 7. 登录

只有同步过的 QQ 号能登录，第一次登录就是注册；冻结的账号登录后只能管理自己的账号。三种方式：

- **口令登录**：网页显示一个 6 位口令，群友把它发给 bot，插件调用确认接口后，网页自动登录。适合电脑上使用。
- **一次性链接登录**：群友找 bot 要登录链接，插件调用接口签发后私聊发给他，点开并确认后登录。适合在手机 QQ 里使用。
- **QQ 邮箱验证码**：输入 QQ 号，验证码发到 `QQ号@qq.com`，10 分钟内有效。不依赖 bot，bot 离线时也能登录。同一个 QQ 号 60 秒内只能发一次，每天最多 10 次。

三种方式都可以在后台单独开关。登录状态保留 90 天，使用时自动续期；设置页可以查看已登录的设备并让其下线。二期加 Passkey 一键登录。

完整流程见[接口 · 流程](api.md#6-流程)。bot 怎么识别口令、怎么发链接由插件决定，论坛只提供接口。

## 8. 内容

### 8.1 版块、帖子与楼层

- 帖子分几类：讨论、问答（可以采纳答案）、投票（第 8.11 节）、抽奖（第 8.13 节）、聊天记录（二期，由合并转发导入，按 QQ 气泡样式显示）。发帖时选类型，还可以选楼主和回复的人是否匿名（第 8.12 节，抽奖帖除外）；类型和匿名设置发出后都不能改。
- 帖子由楼层组成：1 楼是主楼，也就是楼主写的正文；之后的楼层都是回复，按时间排在一条时间线里，没有楼中楼。楼层号固定不变，删除后显示"该楼已删除"，指向某一楼的链接不会错位。
- 回复关系：回复某一层时记下回复的是谁。被回复的那层底部显示"N 个回复"，点开列出回复它的楼层；回复的那层右上角显示被回复的人，点开在上方展开被回复的那一层。两处都可以跳到对应楼层。
- 表情回应：每人对每一层只能留一个，换一个就是替换。点爱心就是点赞；鼠标悬停在爱心上（手机上长按）弹出 10 个表情：❤️ 👍 😆 😮 👏 🎉 🤗 🤔 😭 🐭。每个表情都算一次赞，计入获赞数和通知；不能给自己的楼层点赞。楼层下显示最多的 3 种表情和总数，点开按表情列出是谁。
- 短评：在某一层（含主楼）下面留一句不超过 16 个字的话（emoji 算一个字），显示在这一层的正文下面，带头像，超过 6 条时折叠。点楼层下的小火箭弹出一个浮在页面上的输入框，可以直接选表情。它介于表情回应和回复之间：不占楼层，不算回复数，也不进搜索。每人每层只能留一条，再点小火箭修改或删除；版主点别人的短评可以删除。
- 标签分话题、院校、方向三类。发帖时只能选已有标签，新标签由版主创建，避免标签泛滥。
- 版块的设置：阅读门槛（访客、成员或 L1–L5，见第 8.10 节）、发帖门槛（成员、L1–L5 或只有版主）、默认的帖子类型、审核方式（第 8.4 节）和颜色。能看到版块的成员都能回复。列表和导航里用版块颜色的圆点区分版块。
- 初始版块，上线后在后台建，审核方式都是先发后审；二期加树洞：

  | 版块 | 地址 | 阅读门槛 | 发帖门槛 | 默认类型 |
  | --- | --- | --- | --- | --- |
  | 公告 | `announcements` | 访客 | 只有版主 | 讨论 |
  | 保研问答 | `qa` | 访客 | 成员 | 问答 |
  | 经验分享 | `experience` | 访客 | 成员 | 讨论 |
  | 通知 | `notices` | 访客 | 成员 | 讨论 |
  | 院校交流 | `schools` | 访客 | 成员 | 讨论 |
  | 闲聊 | `chat` | 访客 | 成员 | 讨论 |

### 8.2 正文

- Markdown 由服务端用 markdown-it 渲染，禁用原始 HTML，渲染结果再按白名单过滤，HTML 和原文一起存库。
- 支持 GFM 表格、任务列表、代码高亮（浅色和深色两套）、@提及、引用、表情回应。单个换行就是换行，和聊天里一样。
- @提及写成 `[@鼠鼠](/u/7)`，由编辑器的 @ 自动补全插入；用户没有唯一的用户名，所以按 ID 链接。
- 正文只显示本站上传的图片，别处的图片显示成链接，免得页面去加载陌生网站的文件；站外链接加 `rel="ugc nofollow"`。
- 代码块写明语言才高亮（C、C++、Java、Python、Go、Rust、SQL、Shell 等常用的二十种），其余按纯文本显示。
- 编辑器停靠在页面底部，发帖、回复和编辑都用它，点"发帖"或"回复"才弹出，上面的页面照样能看、能滚动；切到别的页面也一直停着，直到发出或关闭，不想挡着可以收起成一条。发帖时顶部多出标题、版块、标签、类型（讨论、问答或投票）和匿名开关，投票帖还有选项和投票的设置，版块默认是当前所在的版块。电脑上左边输入、右边预览，手机上切换；拖动顶边调整高度并记住，可以全屏。输入框带工具栏（含表情选择器），预览也走服务端渲染，和发布后的效果一致；支持粘贴或拖拽上传图片、@ 自动补全。
- 草稿：参考 linux.do，写的内容自动存到服务器，换台设备也能接着写。
  - 发帖一份，每个帖子的回复各一份；编辑已经发布的楼层不存草稿，原文还在。
  - 停止输入 2 秒后保存一次，内容没变就不发请求；编辑器角落显示是否已保存。离开、刷新或关闭页面时，还没存上的部分用 `fetch` 的 `keepalive` 补发。
  - 再点"发帖"或这个帖子的"回复"时恢复。回到有回复草稿的帖子，编辑器以收起的状态出现在底部；有发帖草稿时，"发帖"按钮显示为"继续草稿"。
  - 点叉号关闭时，有内容就问：保存草稿、放弃，还是继续写。
  - 有草稿时侧栏出现"草稿"，列出全部草稿。发出后草稿删除，180 天没动过的每天清理。
- 每次编辑都保存旧版本，作者和版主可以查看编辑记录。

### 8.3 图片

- 统一处理：解码校验 → 转 WebP（动图转动画 WebP）→ 去掉 EXIF 等元数据。存两档：正文里显示的一档宽度不超过 960px，点开看的大图长边不超过 2048px；动图只存一档。不用 AVIF：编码太慢、太占 CPU，WebP 在 QQ 内置浏览器里也都能用。
- 按原始文件内容去重，单张原图最大 20MB。
- 编辑器里点工具栏的图片按钮、粘贴或拖入都能上传；正文里显示 960 宽的一档并写明宽高，点开是大图。
- 上传后 24 小时内没有被任何内容引用的图片会被清理。
- QQ 图片链接会过期，bot 发帖时论坛会立即下载转存。
- 图片存在服务器的数据卷里（`data/uploads`），由论坛自己提供。服务器上已有的 Zipline 和 AList 不用来放图片：Zipline 在同一台服务器上，占的是同一份出口带宽；AList 背后是 Google Drive，大陆打不开，经 AList 中转又要占服务器的带宽。AList 用来放异地备份（第 12 节）。

### 8.4 内容审核

- 每个版块可以选"先发后审"（默认）或"先审后发"。先审后发的版块里，版主以外的人发的内容先是待审核，通过前只有作者和版主能看到。
- 版主可以隐藏任何帖子和回复，也可以恢复。待审核和已隐藏的内容不算进计数、列表和搜索，别人看到的楼层号跳过它们；主楼跟着帖子。帖子待审核或已隐藏时不能回复。
- 新内容都会产生事件。审核方（例如插件收到事件后调用 LLM）判定后调用接口通过或隐藏，理由写入审计日志。通过、不通过、隐藏、恢复都通知作者，隐藏时带上理由。
- 后台的内容页列出待审核和已隐藏的内容，版主在那里或者楼层的菜单里处理。
- 群友举报的楼层和短评进入举报列表，由版主处理。等级高的成员举报等级比自己低的人时，那一层先隐藏（第 6.6 节）。

### 8.5 搜索

- PostgreSQL 全文检索。中文在应用里按二元切分（"保研夏令营"切成"保研 研夏 夏令 令营"），英文按单词，再存成 tsvector，用 GIN 索引。
- 查询词用同样的方式切分，再按短语匹配。只有一个汉字的查询改为在标题里模糊匹配。
- 筛选：版块、标签、楼主、类型（讨论或问答）、是否已解决、发布时间（一周、一个月、一年内）、只搜标题。排序：相关度（默认，综合相关度和时间，旧的逐渐靠后）、最新发布、最新回复、回复最多、点赞最多。
- 搜索页上方是输入框，下面一行是筛选和排序，和帖子列表用同一套下拉框；条件都写进地址，可以分享。每个帖子一条结果，带最相关的那一层和命中处前后的片段。
- 相似问题：用提问原文检索，返回最相似的几个帖子。群里有人提问时，插件可以先查一下，回一句带链接的"论坛里已经讨论过"。
- 只能搜到自己看得到的内容（第 8.10 节）。

### 8.6 通知与实时

- 通知类型：回复我（回复了我的某一层；回复帖子又没指定哪一层的，算回复楼主）、@我、点赞和短评（各自合并成"某某等 3 人"）、答案被采纳、关注的帖子有新楼层、关注的人发了新帖、升级、抽奖（第 8.13 节）、管理通知。
- 每类通知可以分别开关"站内"和"邮件"。没设置过时，回复我、@我、答案被采纳、管理通知、升级和抽奖发邮件，其余只在站内；抽奖只在中奖和自己发起的开奖了时发邮件。
- 邮件发到 `QQ号@qq.com`，有通知就立刻发，不合并。没登录过论坛的成员也发：他在群里的提问被收录后，有人在论坛上回答，就靠这封邮件知道。
- 从群里收录来的内容不产生通知，只有在论坛上发的才会。
- 发信：
  - 用后台配的发信邮箱，按顺序用。一个发不出去就换下一个，它歇半小时再用：QQ 邮箱发多了会被限制一阵，多配几个就能接上。
  - 待发的邮件和通知在同一个事务里写，提交后马上发；发不出去的每分钟再试，过了一天还没发出去就不发了。每个邮箱都被拒收的地址，直接丢掉。
- 论坛发到 QQ 的只有下面几种，帖子、回复和短评的内容不发到群里：

  | 消息 | 发给谁 | 内容 |
  | --- | --- | --- |
  | 开奖结果 | 群 | 抽奖帖的标题、各奖项中奖的人（@ 本人）和链接；发到哪些群由插件定 |
  | 播报（二期） | 群 | 新帖、热帖、截止提醒、金徽章，只有标题和链接 |
- 帖子页实时显示新回复：有新楼层时底部出现「N 条新回复」，点一下从第一条新的开始看；登录用户顶栏的未读数实时更新。

### 8.7 关注、认可与私信

- **关注**：关注某位群友后，TA 发新帖时收到通知（这类通知可以关掉）。个人主页显示关注数和粉丝数。
- **认可**：对一个人的帮助表示认可。点赞针对一层，认可针对这个人；每人对每人只能认可一次，可以撤回。资料卡和个人主页显示获得的认可数。
- **私信**（二期）：一对一聊天，形式像聊天软件而不是发帖：左边是会话列表，右边按时间排列的消息气泡，实时收发（复用 SSE），支持文字、表情、图片和链接，显示已读。可以屏蔽某人，也可以设置只接收关注的人发来的私信。私信只有双方能看；被举报的消息连同前后几条交给版主处理。新私信也是一类通知，可以开邮件。

### 8.8 徽章（二期）

- 徽章就是成就，分铜、银、金三档。大部分按规则自动授予，例如第一次发帖、第一个被采纳的回答、获赞满 100、连续 30 天活跃；少数由管理员手动授予，例如"已上岸"认证。群荣誉（龙王、群聊之火等）同步过来也算徽章。
- 资料卡显示最近得到的几枚，个人主页显示全部和获得时间。有人得到金徽章时，可以通过事件让插件在群里播报。

### 8.9 阅读记录

登录用户读过哪些楼层、读了多久都会记下来，用来标出没读过的内容，也计入个人统计。访客不记。

- **读过**：一层在屏幕上（露出一半，或者占满半个窗口）累计停留 2 秒，就算读过；页面不在前台时不算。没读过的楼层在楼层号旁边有个小圆点，读过后慢慢淡出。自己发的楼层直接算读过；看不到的楼层（待审核、已隐藏），读过它后面的一楼或者读到能看到的最后一楼时一并算读过，免得帖子一直显示未读，但不计入阅读统计。之后才通过的楼层因此不再显示未读。
- **阅读时间**：页面在前台、并且最近 3 分钟内滚动过或按过键时才计时。
- **上报**：判断和淡出都在浏览器里完成，不等服务器。读过的楼层攒成区间（例如 1–20、480–495），连同阅读秒数，最多每 60 秒发一次；离开帖子或页面切到后台时再发一次，用 `fetch` 的 `keepalive`，关掉页面也能发出去。没有新读的楼层、也没有新的阅读时间就不发，所以一直在读也只是每分钟一个请求，每个几十字节；停下不动就没有请求。
- **存储**：每人每个帖子一行（`thread_users`），读过的楼层存成一个整数区间集合，新读的并进去，相邻的自动合并，不按楼层逐条存。
- **用在哪**：
  - 帖子列表的"新"和"未读"：新是最近 7 天发布、自己还没打开过的帖子，标题后有个小圆点；未读是读过、之后又有新楼层的帖子，标题后显示新楼层数；读到最后一楼的帖子标题颜色淡一些。
  - 从列表点进帖子时，从读过的最高一楼的下一楼开始。
  - 侧栏"已读"列出读过的帖子，按最后阅读时间排。
  - 个人主页的统计：访问天数、阅读时间、读过的帖子数和回复数。
  - 等级的条件（第 6.6 节）。

### 8.10 可见范围

访客指没登录的人和冻结的账号；搜索引擎和 QQ 生成链接卡片时看到的，和访客一样。

- **版块门槛**：版块的阅读门槛可以是访客（公开）、成员或 L1–L5。达不到的人在列表、搜索、推荐和 sitemap 里都看不到这个版块的帖子；访客打开链接是 404，成员打开会看到要几级，版块页上还有去看自己升级进度的链接。版主和管理员不受等级门槛限制。
- **个人开关**：每个人都可以在设置里打开"我的内容不给访客看"，以前发的也算在内。打开后，对访客来说：
  - 这个人发的帖子不出现在列表、搜索和 sitemap 里，打开链接提示登录后查看；分享到 QQ 的卡片只有站点名称。
  - 这个人在别人帖子里的楼层显示为"仅成员可见"，楼层号照常占着；短评不显示。
  - 个人主页只显示名字、头像和等级。
  - 关掉后恢复公开。访客看到的页面有缓存，开关最多 30 秒后生效。
- 没登录过论坛的群友，私聊 bot 登录以后就能打开。
- 不管怎么设，访客都看不到 QQ 号（站点设置可以改成公开）和待审核、已隐藏的内容。成员和 bot 不受个人开关影响。

### 8.11 投票

- 投票帖的主楼下面是一个投票：2–20 个选项，每个不超过 50 字。可以单选或多选，多选可以限制最多选几项。
- 截止时间可以不限，也可以定在 10 分钟以后、一年以内的任意时刻，精确到分钟（网页上还有 1、3、7 天后的快捷选项，按北京时间显示）；发出后不能改，免得落后的一方拖延，楼主和版主可以提前结束。截止前可以改票、撤票，结束后不能再投；帖子锁定后也不能投。
- 结果默认投过票或投票结束后才看得到，免得先看结果再跟风；楼主可以设成随时公开。看得到结果的人能看到每项的票数和比例；一共多少人投了票谁都看得到。
- 实名投票时，看得到结果的成员点开一个选项的票数，列出投了它的人；匿名投票只显示票数（第 8.12 节）。
- 成员才能投，禁言的不能投。L2 起才能发投票帖（第 6.6 节）。选项、单选还是多选、是否匿名发出后都不能改。
- 投票帖和讨论帖一样可以回复。

### 8.12 匿名

发帖时可以选：

| 开关 | 意思 |
| --- | --- |
| 楼主匿名 | 主楼和楼主自己的回复、短评都用匿名名字 |
| 回复匿名 | 楼主以外的人在这个帖子里的回复和短评都匿名；问答帖里叫"回答匿名" |
| 匿名投票 | 投票帖才有：只显示票数，谁投了什么不公开 |

- 设好之后不能改，版主也不能，免得已经匿名说过的话被公开。
- **区分不同的人**：一个帖子里的每个匿名的人有一个编号，按第一次出现的顺序排，楼主匿名时是 1 号。名字显示为"匿名鼠 3"，头像是鼠鼠的剪影，底色由帖子和编号决定。所以同一个帖子里同一个人的名字和颜色始终一样，换个帖子就对不上了。
- **隐藏什么**：匿名的人不显示等级、头衔和角色，点名字和头像打不开资料卡和主页。匿名内容不出现在本人的个人主页和"按楼主搜索"里，不给关注本人的人发"发了新帖"的通知，帖子列表里的参与者头像也不包括匿名的人。通知、事件和邮件里都用匿名名字。表情回应不匿名，点开照常列出是谁。
- **谁知道是谁**：只有本人和管理员。本人在自己的匿名楼层旁看到"我"，"我的帖子"里也有自己的匿名帖。版主看到的也是匿名名字，照样可以审核、隐藏、删除；要禁言匿名的人，找管理员查明身份。
- **管理员查看**：匿名帖子的管理菜单里有"显示真实身份"，每个帖子默认关闭；打开后只在这个管理员自己的页面上把匿名名字换成真实的人，旁边仍标着"匿名"，刷新页面或换个帖子就恢复。每次打开都记一条操作日志。
- 数据库和操作日志里记的都是真实的人。匿名内容照常算进本人的发帖数、获赞数和等级，这些只显示总数，看不出是哪一条。
- "我的内容不给访客看"（第 8.10 节）对本人的匿名内容同样生效。

### 8.13 抽奖

抽奖帖的主楼下面是一张抽奖卡片。论坛到点自动开奖，楼主和管理员都插不上手，开奖结果谁都能复核。L2 起才能发（第 6.6 节）。

- **设置**：发出后都不能改，写错了就取消重发。
  - 奖项：1–10 个，按顺序排，每个写奖品（不超过 50 字）和抽几人（1–100 人），例如"一等奖：机械键盘"抽 1 人、"二等奖：鼠群周边"抽 3 人。
  - 开奖时间：10 分钟以后、一年以内，精确到分钟，同投票的截止时间（第 8.11 节）。
  - 参与方式，二选一：
    - 点卡片上的"参与抽奖"，开奖前可以退出。
    - 回复参与：开奖前在帖子里回复过就算，回复几次都只算一次；开奖时这些回复都已删除或隐藏的不算。
  - 最低等级：L0–L5，默认不限；版主和管理员不受限制。
  - 活动说明、领奖方式写在正文里。
- **谁能参与**：成员，楼主和 bot 除外。禁言中、等级不够的点不了参与；回复参与时，等级不够的回复照常能发，只是不算参与。帖子锁定、待审核或已隐藏时不能点参与。开奖时已经冻结（退群）、被封禁或等级不够的人不算在内。
- **开奖**：到点后一分钟内自动开奖，把参与的人按下面的方法排出先后，依次分给第一个奖项、第二个奖项……。人数不够时，排在前面的奖项先抽满，后面的奖项空着；没人参与就没人中奖。开奖后不能重抽，也不能补抽。帖子删除后不再开奖。
- **复核**：
  - 发帖时论坛生成一个随机种子（32 字节，写成十六进制），卡片上从一开始就公布种子的 SHA-256，开奖后公开种子本身。
  - 每个参与者的排序值是字符串"种子:用户 ID"的 SHA-256（十六进制），按它从小到大排。
  - 核对时，先确认公开的种子算出的 SHA-256 和开奖前公布的一致，再用参与名单自己排一遍，中奖的人应该一样。
  - 种子开奖前保密，没人能提前算出谁会中奖；种子发帖时就定了，开奖时也换不掉。
- **显示**：卡片上有奖项、开奖时间、参与方式、等级要求、参与人数和自己是否参与；开奖后按奖项列出中奖的人，并附上种子和复核的方法。完整的参与名单成员能看；访客只看到人数和中奖的人。
- **通知**：开奖时，参与的人都收到通知，中奖的写明中了哪个奖项；楼主收到开奖通知。中奖和楼主的这两种默认也发 QQ 私聊，没中奖的只发站内通知，免得 bot 一次发出几百条私聊。抽奖取消时，参与的人收到站内通知。
- **取消**：开奖前，楼主和版主可以取消，取消后不再开奖。
- **不匿名**：抽奖帖没有匿名开关，因为中奖的人要找得到楼主，中奖名单也要实名公布。
- **领奖**：成员之间能看到 QQ 号，楼主直接联系中奖的人，论坛不经手。
- **群里**：开奖时产生事件，插件可以把结果发到群里，并 @ 中奖的人；群友也可以通过插件参与抽奖，用的是网页上同样的接口。
- **记录**：参与、退出和取消记在操作日志里；开奖结果记在抽奖本身，谁都能看。

## 9. 页面

- 左侧栏是导航，手机上收进抽屉：全部帖子；登录后有我的帖子、收藏、已读，有草稿时还有草稿；版块，设了等级门槛、自己还没达到的显示锁和需要的等级；话题类的标签（院校和方向太多，放在列表的标签筛选里）。怎么排序和筛选放在列表上方，侧栏不重复。
- 首页、版块页和标签页共用一套筛选：左边是版块和标签两个下拉框，可以叠加；右边是最新、新、未读、热门、待解答，新和未读只对登录用户显示，带数量（见 8.9）。首页顶部显示全站置顶。
- 帖子列表（首页、版块页、标签页、推荐帖子）占满内容区，不设右侧栏。每行左边是标题、版块和标签，标题旁用图标标出置顶、已解决和精华；右边是参与者头像（楼主加最近回复的 4 个人）、回复数、浏览数和最后活动时间。回复数和浏览数按位数用四种颜色，越多越醒目，满 1000 显示成 1.5k。登录用户能看到新帖的圆点和未读的新楼层数，读到最后一楼的帖子标题颜色淡一些；访客按浏览器的访问记录变淡。手机上只留回复数和时间。
- 版块页、标签页（院校标签页汇总这所学校的相关讨论）。
- 帖子页：展开回复关系、没读过的楼层带圆点（见 8.9）、实时显示新回复、已解决标记；底部是回复、收藏、关注按钮和推荐帖子。楼层不一次全部加载：
  - 每次加载 20 层。打开时从起点往后加载：默认是主楼，链接带 `?floor=N` 时从第 N 楼开始，登录用户从列表点进来时从读过的最高一楼的下一楼开始。
  - 滚动接近底部或顶部时，接着加载后面或前面的 20 层；在上方插入楼层时保持当前看的位置不动。
  - 跳到某一楼（拖动时间轴、点"跳到 #N"）：已加载的直接滚过去，没加载的就换成从这一楼开始的一段。已加载的楼层始终是连续的一段，中间不留空。
  - 楼层多时侧栏是可拖动的时间轴，按楼层号定位，总数取帖子的楼层数，不用先加载全部楼层。放不下侧栏的屏幕（包括手机）在右下角显示当前楼层，例如"3 / 52"，点开是同样的楼层导航。
  - 滚动时地址栏跟着改成当前楼层，刷新、分享、返回都回到这一楼。
  - 停在底部时新回复直接接上；不在底部时只更新时间轴的总数。
  - 不执行脚本时（包括搜索引擎），顶部和底部是"前 20 层""后 20 层"的普通链接，照样能翻完全部楼层。
- 发帖、回复和编辑都用底部的编辑器（第 8.2 节），搜索见第 8.5 节。
- 设置：资料（名字、头像、个性签名，都可以改回跟随 QQ）、我的内容不给访客看（第 8.10 节）、代发开关、提醒偏好、登录设备、导出。
- 通知：顶栏的铃铛带未读数，点开是通知页，可以只看未读、全部标为已读；点一条就标为已读并跳到对应的楼层。
- 用户主页：QQ 资料卡（QQ 号、群名片、专属头衔、群龄）、等级、个性签名、关注和认可数、阅读统计（访问天数、阅读时间、读过的帖子和回复数）、徽章（二期），以及发过的帖子和回复；本人还能看到升级进度（第 6.6 节）。
- 资料卡：在任何地方点头像或名字，弹出这个人的小卡片：头像、名字、等级和头衔、个性签名、帖子数、回复数、获赞数、认可数，按钮有私信（二期）、关注、认可和查看主页。
- 管理后台：见第 10 节。
- 配色取自鼠群 logo：带一点暖意的白底、墨绿色文字；主按钮用海一样的青绿色，点缀用太阳的杏色。标志是从洞口探出头的鼠鼠，洞口也是一轮初升的太阳；和主站导航互相链接。站点名称、简介和 Logo 写成常量，页面标题、分享卡片、顶栏和邮件都从那里取。手机优先，兼容 QQ 内置浏览器。
- SEO：服务端渲染。页面带 `description` 和 og 标签（标题、摘要、站点 Logo），QQ 里分享会显示卡片；帖子页的摘要是主楼的前 100 个字。`/sitemap.xml` 列出首页、公开版块和其中的帖子，按最后回复排序，最多 5 万条。访客看不到的内容（第 8.10 节）打不开，也不进 sitemap，所以不会被收录。

## 10. 管理后台

只有管理员能进；版主能看到其中的审核、举报和禁言页面。设置改了立即生效，不用重启。

| 页面 | 内容 |
| --- | --- |
| 概览 | 成员数和已激活数、今日新帖、待审核和举报数、各群最近一次同步的时间、bot 事件流是否在线、数据库和图片占用 |
| 站点 | 公告横幅、QQ 号可见范围、默认审核方式、三种登录方式的开关和提示文案 |
| 邮件 | 发信邮箱，可以配几个，按顺序用：SMTP 服务器、端口、账号、密码（授权码）；每个邮箱各发一封测试邮件 |
| QQ 群 | 关联、停用群，设置主群；查看同步状态和被拦下的全量 |
| 成员 | 按 QQ 号、名字、状态、角色、等级查找；查看资料、升级进度和操作记录；设置角色和等级（L5 只能在这里授予，也可以锁定等级）、禁言、封禁 |
| 版块 | 新建、排序、阅读门槛、发帖门槛、默认类型、审核方式、颜色 |
| 标签 | 新建、改名、改类别、合并、删除 |
| 内容 | 待审核和已隐藏的帖子、回复：通过、不通过、恢复 |
| 举报 | 群友举报的楼层和短评：标为已处理或驳回 |
| bot | 创建 token、选择权限范围、查看最后使用时间、吊销 |
| 操作日志 | 按操作人、对象、动作、IP 筛选；每条带 IP 和设备（第 13 节） |

- **环境变量**：只有 `DATABASE_URL`、`PUBLIC_URL`、`APP_SECRET` 三个。`APP_SECRET` 是 32 字节随机值的 base64，用 `openssl rand -base64 32` 生成，直接作为 AES-256-GCM 的密钥。其余设置都存在数据库里；SMTP 密码这类敏感信息用 `APP_SECRET` 加密后再存，页面上只显示"已设置"。
- **首次部署**：成员要靠 bot 同步，bot token 却要在后台创建，所以第一个管理员要另外进来：在容器里运行 `bootstrap` 命令，给你的 QQ 号生成一次性的管理员登录链接。登录后在后台关联 QQ 群、创建 bot token、配置邮件，之后的成员都由 bot 同步。步骤见[接口 · 首次部署](api.md#68-首次部署)。

## 11. 性能与资源

### 11.1 资源预算

| 部分 | 内存 | 磁盘 |
| --- | --- | --- |
| mousehole 容器 | 空载约 80–110MB（框架本身实测约 70MB），满负载约 150–200MB；V8 堆上限 192MB，容器上限 384MB，给图片处理留出余量 | 镜像约 200MB |
| PostgreSQL | 共用现有实例的共享缓存；连接池最多 10 个连接，约增加 30–80MB | 每层平均 2–5KB（含 HTML、索引和检索数据），十万层约 200–500MB |
| 图片 | 处理时短暂占用，同时最多处理 2 张 | 每张两档合计约 150–400KB；按每天 10 张算，每年约 1.5GB |

图片是磁盘的大头。空间或带宽紧张时可以把图片迁到对象存储，存储层留好了接口。

### 11.2 带宽

服务器出口总带宽 25Mbps（约 3MB/s），和服务器上的其他服务共用。论坛高峰时按不超过 10Mbps 设计；对这台服务器来说，带宽比内存更紧张。

| 内容 | 做法 | 传输大小 |
| --- | --- | --- |
| 页面和接口 | 应用自己压缩（`platform/compress.ts`）：浏览器支持 Brotli 就用 Brotli，否则用 gzip；Brotli 用质量 5、256KB 窗口，每个响应不到 1 毫秒，比 gzip 再小一成左右；事件流不压缩。访客页面的缓存里直接存压缩后的结果。只带用得上的字段，楼层列表默认只返回渲染好的 HTML | 帖子页 HTML 约 10–30KB；站内跳转只取数据，通常不超过 20KB |
| JS 和 CSS | 构建时预先压缩成 Brotli 和 gzip（`scripts/compress-assets.ts`，表情数据也一样），文件名带内容哈希，永久缓存。按路由拆分，管理后台的代码只有管理员会下载。Markdown 渲染和代码高亮只在服务端做，不打包进浏览器 | 首次打开合计不超过 200KB，之后走缓存 |
| 字体和图标 | 只用系统字体，中文网络字体动辄几 MB；图标是按需打包的 SVG | 0 |
| 正文图片 | 正文里只加载显示档，点开才加载大图；懒加载，并写明宽高，避免页面跳动 | 显示档平均约 100KB |
| 头像 | 统一转成 96px 的 WebP，地址带版本号，永久缓存 | 每个约 3KB |
| bot | 推送名单时用 gzip 压缩请求体；事件流平时只有心跳 | 两千人的全量名单约 50KB |

另外：

- **爬虫**：`/robots.txt` 屏蔽 AI 训练爬虫（GPTBot、ClaudeBot、Bytespider 等）和高频采集的爬虫（AhrefsBot、SemrushBot 等）；其他爬虫只收录公开内容，不进后台、个人页面和页面内部取数据的地址。超出限速的请求在 OpenResty 就被拒掉。
- **防盗链**：上传的图片只允许本站页面引用，别的网站的页面引用时返回 403。没有 Referer 的直接访问照常放行，在 QQ 里点开图片链接就是这种情况。头像很小，不限制。
- **排查**：访问日志记录每个响应的字节数，方便找出占带宽的请求。
- **退路**：带宽实在不够时，把图片和静态资源放到 Cloudflare R2 这类不收出口流量费的对象存储，经 Cloudflare 分发。代价是大陆访问会慢一些。

### 11.3 做法

- 未登录访客看到的页面在进程内缓存（`platform/page-cache.ts`，过期后先返回旧页面、后台刷新）：帖子页 10 秒，首页和版块页 30 秒，站内跳转取的页面数据也一样。按地址和压缩格式分开存压缩后的内容和响应头，CSP 的 nonce 因此和页面里的脚本对得上；最多 500 页，最久没用的先丢。带会话 Cookie 的请求不走缓存，登录用户的页面实时渲染。从缓存给出的帖子照样计浏览数。
- 热门排序每 10 分钟在内存里算一次（只算最近 7 天的帖子），不写库。
- 浏览数先在内存里累计，每分钟批量写一次。
- 数据库层面的优化见[数据表 · 约定](data-model.md#约定)。

### 11.4 验收

- 上线前用 `pnpm load-test` 压测：100 个并发读者，一半是访客打开分享的链接，成员混合浏览、点赞、回复，p95 低于 100ms，内存不超出预算。只对本地或预发的服务器跑，不对正式站点。
- 两千人的完整名单做一次全量同步，在 1 秒内完成；没有变化时不产生任何写入。
- 热点查询在 CI 里用 `EXPLAIN` 检查，必须走索引（`server/indexes.test.ts`：造一年的帖子和楼层，打开常用的页面和接口，记下所有查询再看执行计划）。
- 访客第一次打开帖子页，除图片和头像外传输不超过 200KB；再次打开不超过 30KB。

## 12. 部署与运维

- **镜像**：基于 `node:26-slim` 多阶段构建（`Dockerfile`），以 `node` 用户（uid 1000）运行，V8 堆上限 192MB，自带 `/healthz` 健康检查。CI 在每个 PR 上确认镜像能构建；在 `main` 上打 `v1.2.3` 这样的版本标签时，GitHub Actions 构建镜像并推到 `ghcr.io/mousebaoyan/mousehole`（标签是版本号和 `latest`）。这个包设为公开，服务器不用登录就能拉取；镜像里没有密钥，源码本来也是公开的。服务器只拉镜像，不在服务器上编译。
- **compose**：见 `deploy/compose.yml`。`mousehole` 服务加入 `1panel-network`，通过容器名连接 PostgreSQL；端口只监听 `127.0.0.1:3080`（3000 已被占用）；`data/`（上传的图片和头像）挂载为数据卷；内存上限 384MB，日志轮转。更新就是 `docker compose pull && docker compose up -d`；停止时先写入内存里的浏览数。
- **数据库**：在 1Panel 里新建 `mousehole` 库和同名账号，这个账号只有 `mousehole` 库的权限；连接串通过环境变量传入。
- **迁移**：启动时自动执行，先取 advisory lock，防止重复执行。
- **备份**：本机和异地各存一份。异地放在服务器上 AList 挂的 Google Drive 里，通过 AList 的 WebDAV 上传。

  | 内容 | 方式 | 保留 |
  | --- | --- | --- |
  | 数据库 | 1Panel 的计划任务每天凌晨 4 点 `pg_dump` | 本机 7 份，异地 30 份 |
  | `data/`（图片和头像） | 每天增量复制到异地，只传新增和变了的文件 | 图片按内容命名，写好后不再改，删掉的在备份里也留着 |

  - 上传占服务器的出口带宽，所以放在凌晨：数据库压缩后几十 MB，图片每天新增几 MB。
  - 每季度把备份恢复到本地试一次，确认能用。服务器快照照常做，作为整机的兜底。
  - 用 1Panel 的 WebDAV 备份账号还是 rclone，部署时看服务器上的条件再定（第 14 节 M10）。
- **日志**：论坛只往 stdout 写 JSON 日志，Docker 按 10MB 一个文件轮转，留 5 个（`deploy/compose.yml`）。OpenResty 的访问日志用 1Panel 的"切割网站日志"计划任务每天切割，留 30 份。操作日志（`audit_logs`，第 10 节）在库里永久保留，随数据库一起备份，每年预计几万到十几万行，占用很小。
- **反代**：在 1Panel 的 OpenResty 里新建站点，配置见 `deploy/openresty.conf`。SSE 路径关闭缓冲（`proxy_buffering off`）并延长超时；上传大小上限 20MB。开启 HTTP/2 和 HTTP/3，跨境链路丢包时 HTTP/3 更稳。站点关闭 gzip，压缩交给应用：服务器上的 OpenResty 没有 Brotli 模块，默认配置也不压缩 JSON。转发时设置 `X-Real-IP`，并按 IP 限制连接数和请求速率。
- **域名**：Cloudflare 上设为仅 DNS（灰云），直连服务器。开代理反而会让大陆访问绕路，变慢。
- **监控**：`/healthz` 接入服务器上已有的 Gatus（`deploy/gatus-endpoints.json`：容器内和经过公网各一条）；页面可以配置 Umami 统计；日志以 JSON 格式输出到 stdout。
- **定时任务**：在进程里运行（`platform/schedule.ts`），失败只记日志，下一轮再试。每分钟写入浏览数，发出待发的邮件；每小时检查升级，刷新满一天的头像；每天复查 L4 的等级，清理过期的会话、登录口令和链接、邮件验证码，7 天前的幂等记录，上传后一天没用上的图片，7 天前的事件，半年前读过的通知，以及 180 天没动过的草稿。
- **本地开发**：用 docker compose 起一个本地 PostgreSQL；`scripts/mock-bot` 模拟插件，推送成员、代发内容、消费事件，不用真 QQ 号也能测完整流程。

## 13. 安全与隐私

- **QQ 号**：对登录的成员、bot 和管理员可见；访客看到的页面和接口里都没有（站点设置可以改成公开）。
- **bot token**：随机生成，只显示一次，库里只存哈希；按范围授权，可以随时吊销，并记录最后使用时间。
- **会话**：Cookie 设为 HttpOnly、Secure、SameSite=Lax，库里只存哈希。
- **后台设置里的密钥**：SMTP 密码等用 `APP_SECRET` 加密存储，接口和页面都不返回明文。
- **CSRF**：用 Cookie 认证的写请求校验 Origin。
- **XSS**：Markdown 禁用原始 HTML，输出再按白名单过滤；设置 CSP。
- **SSRF**：转存图片只允许 QQ 的图片域名，限制大小和超时，不跟随跳转到其他域名。头像只从固定的 `q1.qlogo.cn` 地址拉，地址里只有 QQ 号，同样限制大小和超时、不跟随跳转。
- **上传**：图片和头像都用 sharp 解码判断真实格式，限制像素总数，防止解压炸弹；重新编码并去掉元数据。
- **验证码**：邮件验证码 10 分钟内有效，输错 5 次作废。
- **对外暴露**：只有 OpenResty 对外，论坛容器的端口只监听本机，数据库不对外。服务器防火墙只放行 80、443 和 SSH。
- **客户端 IP**：只认 OpenResty 设置的 `X-Real-IP`，不信任请求自带的 `X-Forwarded-For`。限流和登录记录都依赖它。
- **限流**：分两层。OpenResty 按 IP 限制连接数和请求速率，先挡掉刷接口和采集；应用里再细分：申请口令和邮件验证码按 IP 和 QQ 号；发帖和回复按用户（每人每小时 20 个帖子、每 10 分钟 60 条回复），bot 按 token（每个 token 代所有人合计每分钟 120 次），挡住刷屏和失控的插件。
- **请求大小**：JSON 请求体默认不超过 1MB，成员全量同步不超过 4MB，图片不超过 20MB；gzip 请求体按解压后的大小计算，防止压缩炸弹。慢速连接由 OpenResty 和 Node 的超时一起断开。
- **响应头**（`platform/security-headers.ts`）：HSTS；CSP 只允许本站脚本，内联脚本带 nonce，样式允许内联（组件会设 `style` 属性），图片只能来自本站；`X-Content-Type-Options: nosniff`；`Referrer-Policy: strict-origin-when-cross-origin`；`frame-ancestors 'none'` 防止页面被嵌入别的网站做点击劫持。本地开发走 HTTP，不发 CSP 和 HSTS，免得挡住 Vite 热更新的内联脚本。
- **容器**：用非 root 用户运行，根文件系统只读，只有图片目录和临时目录可写；开启 `no-new-privileges`，去掉不需要的 capabilities。
- **依赖和 CI**：pnpm 只安装发布满 1 天的版本，避开刚被投毒的包；只有白名单里的依赖能执行安装脚本。CI 按锁文件安装。GitHub Actions 按最小权限运行，第三方 Action 固定到具体的提交。仓库开启了 secret 扫描、推送拦截和依赖漏洞提醒。
- **大流量攻击**：攻击流量很容易占满 25Mbps。应急办法是把域名临时切到 Cloudflare 代理，防火墙只放行 Cloudflare 的 IP 段，攻击过去后再切回仅 DNS。
- **导出**：用户可以导出自己的全部内容，冻结的账号也可以。账号永久保留，暂不提供注销（第 6.1 节）。
- **访客能看到的范围**：版块门槛和个人开关，见第 8.10 节。
- **匿名内容**：页面、接口、事件和通知里都只有匿名名字，只有本人和管理员知道是谁，管理员查看要留操作日志（第 8.12 节）。
- **操作日志**（`audit_logs`）：用来事后查清是谁做了什么。
  - 记下所有改动：登录、退出、让设备下线；发帖、回复、编辑、删除、短评、举报、投票；改资料、设置和头像；版主和管理员的全部操作；bot 的全部写操作；管理员查看匿名身份。浏览、点赞和表情回应、收藏、关注、阅读记录、草稿不记，它们本身就记着是谁，或者无关紧要。
  - 每条有时间、操作人（bot 代操作时还有经由的 token 和让 bot 做事的人）、IP、User-Agent、动作、对象，以及看得出改了什么的字段：标题、正文的开头、改前改后的值、理由。
  - 只有管理员能看，可以按操作人、动作、对象和 IP 筛选；永久保留。
