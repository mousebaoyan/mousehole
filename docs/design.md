# 鼠洞 · 总体设计

> 状态：草案，待评审。表结构见[数据表](data-model.md)，接口细节见[接口](api.md)。

## 1. 目标

- **沉淀内容**：群里的问答、经验和通知存到论坛，长期保留，群被封也不会丢。
- **和 QQ 群打通**：一个 QQ 号就是一个账号，资料和群里看到的一致。AstrBot 插件可以通过接口使用论坛的几乎全部功能，并指定以哪位群友的身份操作。
- **轻量**：和其他服务共用一台服务器，论坛进程常驻内存 150MB 左右，支撑上千人的群和两位数并发。

暂不做：站内私信（QQ 里就能私聊）、联邦协议。

## 2. 已定决策

| 事项 | 决定 |
| --- | --- |
| 名称 | 鼠洞 |
| 仓库与域名 | `mousebaoyan/forum`，`bbs.mousebaoyan.cn` |
| 实现方式 | 自研，借鉴 Discourse、Apache Answer、V2EX、贴吧和 NGA 的设计 |
| 技术栈 | Nuxt 4 全栈，页面和接口在同一个 Node 进程 |
| 数据库 | 复用服务器上 1Panel 的 PostgreSQL 18，新建独立的库和账号；暂不用 Redis |
| 身份 | 一个 QQ 号就是一个账号，昵称、群名片、头像、群角色从 QQ 同步 |
| 登录 | 三种都支持：口令登录、一次性链接登录（这两种经 bot 验证）、QQ 邮箱验证码 |
| 公开范围 | 公开可读；个别版块可设为仅成员可见，并禁止搜索引擎收录 |
| 发帖门槛 | 群成员，包括已经退群的老成员；发帖权限只受论坛的禁言和封禁限制 |
| QQ 号 | 不做隐私处理，成员之间可见，和群里一样；访客默认看不到。匿名功能以后单独设计 |
| bot 代发 | 标注来源；本人可以编辑、删除，也可以关闭代发；审计日志记录操作人 |
| 内容审核 | 论坛提供审核状态、接口和事件，具体审核以后接入 LLM |

退群不影响发帖，是因为清理不活跃成员时也会踢人，被踢不代表违规。需要禁止某人发帖时，由版主禁言或管理员封禁；插件也可以在 QQ 里拉黑某人时调用接口同步。

## 3. 为什么自研

现成论坛都要深度改造，才能满足三件核心需求：QQ 号即身份、bot 代任意群友操作、通过 bot 登录。

| 项目 | 技术栈与资源 | 代任意用户操作 | 主要问题 |
| --- | --- | --- | --- |
| Discourse | Ruby + PostgreSQL + Redis，官方建议 2GB 以上内存 | 支持（`Api-Username`） | 太重 |
| Flarum | PHP + MySQL | 支持（API key + userId） | QQ 登录、成员同步要写 PHP 扩展 |
| NodeBB | Node + Redis 或 MongoDB | 支持（master token + `_uid`） | QQ 登录、成员同步要写插件 |
| Apache Answer | Go，问答型 | 不支持 | 只适合纯问答 |

QQ 互联也用不上：它要求域名完成 ICP 备案（服务器在香港，无法备案），而且只返回 openid，拿不到 QQ 号，没法和群里的身份对应起来。

## 4. 架构

```text
QQ 群（可以有多个）
  ⇅ NapCat
AstrBot + 论坛插件
  │  REST：Bearer token + X-Act-As: qq:号码
  │  SSE 事件流：插件主动连接，断线后按游标续传
  ▼
OpenResty（1Panel，TLS） ◀── 浏览器
  ▼
forum 容器（Nuxt 4）── 图片目录（数据卷）
  ├─ 页面：服务端渲染，浏览器端接管交互
  ├─ /api/v1：网页和 bot 共用的 JSON 接口
  ├─ SSE：网页实时更新、bot 事件流
  └─ 定时任务：批量写浏览数、清理过期数据、刷新头像
  ▼  1panel-network
1Panel 的 PostgreSQL 18（forum 库）
```

- **一个进程**：页面和接口在同一个 Nuxt 进程里，服务端渲染页面时在进程内调用接口，不经过网络。
- **接口是唯一入口**：业务逻辑都在服务层（`server/services`），网页和 bot 都通过 `/api/v1` 调用。网页能做的，bot 都能做。
- **插件主动连接**：插件所在的机器可以在内网，只要能访问外网即可。插件主动调用接口、主动订阅事件流，论坛不会反向连接插件。
- **论坛不依赖 bot**：bot 离线时论坛照常使用，新用户也能用邮箱验证码登录。期间产生的事件留在论坛里，bot 恢复后补发。

## 5. 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Nuxt 4（Vue 3 + TypeScript），Node.js LTS | 服务端渲染，SEO 和 QQ 链接卡片都正常；服务端（Nitro）比 Next.js 轻 |
| 数据库 | PostgreSQL 18（复用 1Panel 实例）+ Drizzle ORM + postgres.js | 上千人、存几年的数据量没有压力；备份跟着 1Panel 和服务器快照走 |
| 搜索 | PostgreSQL 全文检索（tsvector + GIN），中文在应用里二元切分 | 实例里没有中文分词扩展，这样做不用装任何扩展 |
| 缓存 | 进程内缓存 | 单进程足够，暂不用 Redis。以后要跑多个进程时，缓存和限流换成 Redis，实时推送用 PostgreSQL 的 LISTEN/NOTIFY |
| 校验与文档 | zod 定义请求和响应，生成 OpenAPI | 插件可以直接据此生成 Python 客户端 |
| 正文 | Markdown（markdown-it），服务端渲染并过滤；Shiki 代码高亮 | 网页和 bot 发的内容走同一套渲染，高亮和主站一致 |
| 图片 | sharp | 转 WebP、去 EXIF、限尺寸 |
| 邮件 | nodemailer + SMTP | 建议用一个 QQ 邮箱的 SMTP 发信，发往 qq.com 不容易进垃圾箱 |
| 界面 | 自己写样式，沿用主站的配色变量和深色模式；弹窗、菜单等用 Reka UI | 和主站风格一致，不引入大型组件库 |
| 实时 | SSE | 只需要服务端单向推送，经过反向代理也简单 |
| 测试 | Vitest（单元、接口）、Playwright（关键页面）、k6（压测） | 接口测试连真实的 PostgreSQL |
| 部署 | GitHub Actions 构建镜像推到 GHCR，服务器用 docker compose 拉取运行 | 服务器不编译 |

不单独起 Go 或 Rust 接口服务：公开页面需要服务端渲染，Node 进程本来就省不掉。再单独起一个接口服务，总内存差不多，却多一种语言和一个容器。

## 6. 身份、成员与权限

### 6.1 账号与资料

- 一个 QQ 号对应一个账号。插件同步群成员时为每位成员建号，这时账号是"未激活"状态；本人第一次登录后激活。bot 代发的内容一开始就记在本人名下。
- 显示名优先用本人设置的名字，其次用主群的群名片，最后用 QQ 昵称。
- 资料卡和群里看到的一致：QQ 号、群名片、群头衔、群等级、入群时间。
- QQ 号对登录的成员可见。访客和搜索引擎看不到，就像群外的人看不到群成员一样，也防止被批量抓取；站点设置可以改成对所有人公开。
- 头像从 QQ 头像接口拉取，缓存成 WebP 后由论坛提供（`/avatars/{用户ID}.webp`），访客看到的页面里也就不会出现带 QQ 号的头像链接。每天刷新一次。

### 6.2 群与成员同步

- 后台可以关联多个 QQ 群。群被封后建了新群，只要关联新群号，账号和内容都不受影响；被封的旧群停用即可。
- 插件定期推送完整成员名单；有人进群、退群、被踢、改群名片、被设为或取消管理员时，实时推送变动。
- 成员状态：在任意一个启用的群里为 `member`，都不在了为 `former`。两种状态都能发帖。
- 角色跟随群角色：群主对应管理员，群管理员对应版主，其余为普通用户，取所有启用的群里最高的那个。管理员可以手动指定角色并锁定，之后同步不再覆盖。bot 自己的账号固定为 `bot` 角色。

### 6.3 权限

| 操作 | 谁可以 |
| --- | --- |
| 浏览公开版块 | 所有人 |
| 浏览仅成员版块、查看 QQ 号 | 已登录的成员 |
| 发帖、回复、点赞、收藏、举报 | 已登录且未被禁言的成员 |
| 编辑自己的内容；删除自己的回复、没人回复过的主题 | 作者 |
| 采纳答案 | 主题作者、版主 |
| 置顶、精华、锁定、移动、隐藏、删除任意内容；管理标签 | 版主 |
| 审核内容、处理举报、禁言 | 版主 |
| 封禁、设置角色、管理版块、站点设置、bot token、关联 QQ 群 | 管理员 |

禁言后仍能登录和浏览，但不能发帖、回复和点赞；封禁后不能登录。

### 6.4 bot 代操作

细节见[接口 · bot 认证与代操作](api.md#2-bot-认证与代操作)，要点：

- 每个 bot 一个 token，按范围授权：只读、代发、版主操作、管理、成员同步、登录、事件。
- `X-Act-As: qq:号码` 指定以谁的身份操作，同时受 token 范围和这个人自己的权限限制，不会越权。
- `X-Operator` 记录是谁让 bot 操作的。代表别人操作时，论坛会检查操作人是不是版主或管理员，插件出了 bug 也不会被普通群友利用。
- 成员可以关闭"允许代发"，之后只有他本人能让 bot 以他的身份操作。
- 代发的内容标"来自群聊"或"由机器人代发"，本人可以编辑和删除；所有代操作写入审计日志。

## 7. 登录

只有已同步的成员能登录。三种方式：

- **口令登录**：网页显示一个 6 位口令，群友把它发给 bot，插件调用确认接口后，网页自动登录。适合电脑上使用。
- **一次性链接登录**：群友找 bot 要登录链接，插件调用接口签发后私聊发给他，点开并确认后登录。适合在手机 QQ 里使用。
- **QQ 邮箱验证码**：输入 QQ 号，验证码发到 `QQ号@qq.com`，10 分钟内有效。不依赖 bot，bot 离线时也能登录。同一个 QQ 号 60 秒内只能发一次，每天最多 10 次。

登录状态保留 90 天，使用时自动续期；设置页可以查看已登录的设备并让其下线。二期加 Passkey 一键登录。

完整流程见[接口 · 流程](api.md#5-流程)。bot 怎么识别口令、怎么发链接由插件决定，论坛只提供接口。

## 8. 内容

### 8.1 版块、主题与楼层

- 主题分三类：讨论、问答（可以采纳答案）、聊天记录（二期，由合并转发导入，按 QQ 气泡样式显示）。
- 回复分楼层和楼中楼。楼层号固定不变，删除后显示"该楼已删除"，页码不会错位。
- 标签分话题、院校、方向三类。发帖时只能选已有标签，新标签由版主创建，避免标签泛滥。
- 初始版块建议（待定）：公告、保研问答、经验分享、通知与截止日期、院校交流、闲聊；二期加树洞。

### 8.2 正文

- Markdown 由服务端用 markdown-it 渲染，禁用原始 HTML，渲染结果再按白名单过滤，HTML 和原文一起存库。
- 支持 GFM 表格、任务列表、代码高亮（浅色和深色两套）、@提及、引用、表情回应。
- 编辑器：输入框加工具栏，预览也走服务端渲染，和发布后的效果一致；支持粘贴或拖拽上传图片、@ 自动补全，草稿自动保存在浏览器里。
- 每次编辑都保存旧版本，作者和版主可以查看编辑记录。

### 8.3 图片

- 统一处理：解码校验 → 长边缩到 2048px 以内 → 转 WebP（动图转动画 WebP）→ 去掉 EXIF 等元数据。
- 按原始文件内容去重，单张原图最大 20MB。
- 上传后 24 小时内没有被任何内容引用的图片会被清理。
- QQ 图片链接会过期，bot 发帖时论坛会立即下载转存。

### 8.4 内容审核

- 每个版块可以选"先发后审"（默认）或"先审后发"。先审后发的内容在通过前只有作者和版主能看到。
- 新内容都会产生事件。审核方（例如插件收到事件后调用 LLM）判定后调用接口通过或隐藏，理由写入审计日志。
- 群友举报的内容进入举报列表，由版主处理。
- 转发到 QQ 之前要不要再审一遍，由插件决定。

### 8.5 搜索

- PostgreSQL 全文检索。中文在应用里按二元切分（"保研夏令营"切成"保研 研夏 夏令 令营"），英文按单词，再存成 tsvector，用 GIN 索引。
- 查询词用同样的方式切分，再按短语匹配，结果综合相关度和时间排序。只有一个汉字的查询改为在标题里模糊匹配。
- 相似问题：用提问原文检索，返回最相似的几个主题。群里有人提问时，插件可以先查一下，回一句"论坛里已经讨论过"。
- 仅成员版块的内容只有成员能搜到。

### 8.6 通知与实时

- 通知类型：回复我、楼中楼回复我、@我、引用我、点赞（合并成"某某等 3 人"）、答案被采纳、关注的主题有新楼层、管理通知。
- 每类通知可以分别开关"站内"和"QQ 提醒"。QQ 提醒通过事件交给插件发送。
- 主题页实时显示新回复；登录用户实时收到通知和未读数。

## 9. 页面

- 首页：最新、热门、待解答三个标签，顶部显示全站置顶。
- 版块页、标签页（院校标签页汇总这所学校的相关讨论）。
- 主题页：楼层分页、展开楼中楼、跳到指定楼层、实时显示新回复、已解决标记。
- 发帖与编辑、搜索、通知、设置（资料、代发开关、提醒偏好、登录设备）。
- 用户主页：QQ 资料卡（QQ 号、群名片、群头衔、群等级、入群时间）、发过的主题和回复。
- 后台：版块与标签、成员与角色、待审核与举报、bot token、站点设置、操作日志。
- 风格沿用主站，导航互相链接；手机优先，兼容 QQ 内置浏览器。
- SEO：服务端渲染，带 og 标签（QQ 里分享会显示卡片），提供 sitemap。仅成员版块的内容不进 sitemap，并加 noindex。

## 10. 性能与资源

### 10.1 资源预算

| 部分 | 内存 | 磁盘 |
| --- | --- | --- |
| forum 容器 | 常驻约 100–150MB；容器上限 384MB，V8 堆上限 256MB | 镜像约 200MB |
| PostgreSQL | 共用现有实例的共享缓存；论坛连接池最多 10 个连接，约增加 30–80MB | 每条回复平均 2–5KB（含 HTML、索引和检索数据），十万条约 200–500MB |
| 图片 | 处理时短暂占用，同时最多处理 2 张 | 每张约 100–300KB；按每天 10 张算，每年约 1GB |

图片是磁盘的大头。空间紧张时可以把图片迁到对象存储，存储层留好了接口。

### 10.2 做法

- 未登录访客看到的页面用 Nitro 缓存（过期后先返回旧页面、后台刷新）：主题页 10 秒，列表页 30 秒。登录用户的页面实时渲染。
- 热门排序每 10 分钟在内存里算一次（只算最近 7 天的主题），不写库。
- 浏览数先在内存里累计，每分钟批量写一次。
- 数据库层面的优化见[数据表 · 约定](data-model.md#约定)。

### 10.3 验收

- 上线前用 k6 压测：100 个并发用户混合浏览、回复、点赞，p95 低于 100ms，内存不超出预算。
- 热点查询在 CI 里用 `EXPLAIN` 检查，必须走索引。

## 11. 部署与运维

- **镜像**：GitHub Actions 运行测试并构建镜像，推到 `ghcr.io/mousebaoyan/forum`。服务器只拉镜像，不在服务器上编译。
- **compose**：`forum` 服务加入 `1panel-network`，通过容器名连接 PostgreSQL；端口只监听 `127.0.0.1`；图片目录挂载为数据卷；配置健康检查（`/healthz`）和日志轮转。
- **数据库**：在 1Panel 里新建 `forum` 库和同名账号，这个账号只有 `forum` 库的权限；连接串通过环境变量传入。
- **迁移**：启动时自动执行，先取 advisory lock，防止重复执行。
- **备份**：用 1Panel 的计划任务每天备份 `forum` 库；数据库和图片目录也都包含在服务器快照里。
- **反代**：在 1Panel 的 OpenResty 里新建站点。SSE 路径关闭缓冲（`proxy_buffering off`）并延长超时；上传大小上限 20MB。
- **域名**：Cloudflare 上设为仅 DNS（灰云），直连服务器。开代理反而会让大陆访问绕路，变慢。
- **监控**：`/healthz` 接入服务器上已有的 Gatus；页面可以配置 Umami 统计；日志以 JSON 格式输出到 stdout。
- **定时任务**：每分钟写入浏览数、清理过期的口令和链接；每天清理过期的事件、幂等记录、会话和无用图片，并刷新头像。
- **本地开发**：用 docker compose 起一个本地 PostgreSQL；`scripts/mock-bot` 模拟插件，推送成员、代发内容、消费事件，不用真 QQ 号也能测完整流程。

## 12. 安全与隐私

- **QQ 号**：对登录的成员、bot 和管理员可见；访客看到的页面和接口里都没有（站点设置可以改成公开）。
- **bot token**：随机生成，只显示一次，库里只存哈希；按范围授权，可以随时吊销，并记录最后使用时间。
- **会话**：Cookie 设为 HttpOnly、Secure、SameSite=Lax，库里只存哈希。
- **CSRF**：用 Cookie 认证的写请求校验 Origin。
- **XSS**：Markdown 禁用原始 HTML，输出再按白名单过滤；设置 CSP。
- **SSRF**：转存图片只允许 QQ 的图片域名，限制大小和超时，不跟随跳转到其他域名。
- **上传**：用 sharp 解码判断真实格式，限制像素总数，防止解压炸弹；重新编码并去掉元数据。
- **验证码**：邮件验证码只存哈希，输错 5 次作废。
- **限流**：申请口令和邮件验证码按 IP 和 QQ 号，发帖和回复按用户，bot 按 token。
- **注销与导出**：用户可以注销账号，选择保留内容（署名改为"已注销用户"）或一并删除；也可以导出自己的全部内容。
- **匿名内容**（二期）：公开页面和事件里都不带作者，只有管理员能在后台看到。
